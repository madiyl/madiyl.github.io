# 导航点击跳转与设计前数据恢复计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 去掉当前横向分页/横滑浏览方式，恢复为纵向顺序页面，并确保设计阶段之前的封面区与人员介绍模块重新正常显示。

**Architecture:** 保留现有顶部封面区、人员介绍模块和各阶段组件本身，不再把内容模块装进单页横向分页容器。导航条从“分页切换按钮”改回“点击跳转到对应模块”的受控锚点导航，这样页面重新回到纵向信息流，设计阶段之前的数据不会因为分页隐藏而消失。

**Tech Stack:** React 18、TypeScript、Tailwind CSS、现有 `RenovationJourneyPage` 页面装配与各阶段组件

---

## Summary

本轮调整只聚焦两件事：

1. 取消当前“横滑 / 横向分页”的内容浏览方式，导航条改成点击跳转到对应模块。
2. 恢复“设计阶段之前”的数据展示，也就是让顶部封面区和人员介绍模块重新处于设计阶段之前的正常页面流里，而不是被单页分页逻辑折叠掉。

## Current State Analysis

### 当前问题的实际来源

- [`src/pages/RenovationJourneyPage.tsx`](file:///Users/bytedance/madiyl.github.io/src/pages/RenovationJourneyPage.tsx)
  - 顶部封面区仍然存在。
  - `PeopleIntroStage` 也仍然存在，并作为分页容器的第一页被渲染。
  - 但页面主内容现在被改成：
    - `contentPages`
    - `activePageIndex`
    - 横向 `flex + overflow-x-auto + snap-x`
    - `scrollToPage(index)` 通过 `scrollIntoView` 切换“页”
  - 这意味着：
    - 设计阶段之前的人员介绍不会和设计阶段同时存在于同一条纵向页面流里
    - 一旦当前页切换到设计阶段，人员介绍就被“藏在左侧页”里
    - 用户主观上会感知成“设计阶段之前的数据没了”

### 当前导航为何不符合诉求

- 当前导航条已经不是原来的锚点导航，而是分页按钮：
  - `onClick={() => scrollToPage(index)}`
  - 当前页高亮跟随 `activePageIndex`
- 用户本轮明确要求：
  - “不要横滑效果了，点击导航跳转”
- 这说明本轮目标不是保留分页切换的外壳，而是回到“点击导航直接跳到页面对应模块”的语义。

### 当前数据本身并没有丢

- [`src/lib/defaultContent.ts`](file:///Users/bytedance/madiyl.github.io/src/lib/defaultContent.ts)
  - `people` 默认数据仍在。
  - `meta` 封面数据也仍在。
- [`src/components/stages/PeopleIntroStage.tsx`](file:///Users/bytedance/madiyl.github.io/src/components/stages/PeopleIntroStage.tsx)
  - 人员介绍组件已存在且可正常渲染。

**结论：**
- 这不是内容数据被删除的问题。
- 根因是页面装配方式从纵向流改成了单页横向分页，导致设计阶段之前的数据不再自然显示在设计阶段之前。

## Proposed Changes

### 1. 移除横向分页容器，恢复纵向模块顺序

**文件：**
- 修改：[`src/pages/RenovationJourneyPage.tsx`](file:///Users/bytedance/madiyl.github.io/src/pages/RenovationJourneyPage.tsx)

**变更内容：**
- 删除当前与横向分页相关的状态和引用：
  - `activePageIndex`
  - `activePageHeight`
  - `pageRefs`
  - `contentPages`
  - `useEffect` 里的高度同步逻辑
  - `scrollToPage(index)` 的分页滚动逻辑
- 删除当前横向分页容器：
  - `overflow-hidden transition-[height]`
  - `flex snap-x snap-mandatory overflow-x-auto`
  - `min-w-full shrink-0 snap-start`
- 把内容恢复成普通纵向顺序渲染：
  1. `PeopleIntroStage`
  2. `DesignStage`
  3. `MaterialsStage`
  4. `AppliancesStage`
  5. `ConstructionStage`
  6. `SoftFurnishingStage`

**原因：**
- 只有回到真实纵向页面流，设计阶段之前的内容才会稳定地出现在设计阶段之前。
- 这也是最直接满足“弄回来”的做法，不引入新的交互猜测。

### 2. 导航从分页按钮改成锚点跳转

**文件：**
- 修改：[`src/pages/RenovationJourneyPage.tsx`](file:///Users/bytedance/madiyl.github.io/src/pages/RenovationJourneyPage.tsx)

**变更内容：**
- 将当前 `navItems` 恢复为带 `href` 的结构，例如：
  - `#people`
  - `#design`
  - `#materials`
  - `#appliances`
  - `#construction`
  - `#soft`
- 导航 UI 从 `button` 改回 `a` 标签，点击时直接跳到对应模块。
- 保留现有 sticky 导航外观，不改视觉风格，只改交互语义。

**原因：**
- 用户明确说的是“点击导航跳转”，不是“点击导航切页”。
- 锚点跳转最符合当前页面结构，也不再制造“只显示一页”的副作用。

### 3. 确保人员介绍模块在设计阶段之前重新可见

**文件：**
- 修改：[`src/pages/RenovationJourneyPage.tsx`](file:///Users/bytedance/madiyl.github.io/src/pages/RenovationJourneyPage.tsx)

- 把 `PeopleIntroStage` 放回设计阶段之前的普通内容流。
- 保持其 `id="people"`，方便导航直接跳转。
- 不调整该模块自身的数据结构、卡片内容或编辑逻辑。

**原因：**
- 用户当前反馈的是“设计阶段之前的数据都没有了”，这块最直接对应的新增模块就是 `PeopleIntroStage`。
- 本轮只做恢复展示，不继续扩展人员介绍能力。

### 4. 保留现有已完成的数据能力，避免无关回退

**文件：**

**变更内容：**
- 保留这些已经完成且未被本轮否定的功能：
  - `people` 数据结构
  - 电器 `productUrl`

- 本轮不回退这些能力，只回退“横向分页”的交互方案。

**原因：**
- 用户只否定了横滑效果，没有否定人员介绍模块或电器链接能力本身。
- 改动应聚焦，不做额外回退。

## Assumptions & Decisions

1. “设计阶段之前的数据都没有了”按页面装配问题处理，而不是数据源丢失问题处理。
2. 顶部封面区继续保留在最上方，人员介绍模块位于封面区之后、设计阶段之前。
3. 导航“点击跳转”采用页面锚点语义，而不是按钮切换状态页。
4. 本轮只移除横滑/分页效果，不回退 `people` 模块和电器商品链接功能。
5. 现有 sticky 导航样式可以继续保留，主要调整行为，不要求重做视觉设计。
