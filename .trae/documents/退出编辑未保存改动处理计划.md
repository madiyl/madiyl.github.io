# 退出编辑未保存改动处理计划

## Summary

当前“退出编辑”按钮只会关闭编辑态，不会自动保存，也不会提示用户未保存改动。  
本次要把它改成更符合预期的交互：

- **有未保存改动时**：点击“退出编辑”先弹确认
- 确认弹层提供 3 个动作：
  - 保存并退出
  - 不保存退出
  - 继续编辑
- **无未保存改动时**：直接退出编辑态

基于当前代码，退出编辑相关逻辑如下：

    - `setEditMode(false)`
    - 清空密码与鉴权错误
    - 关闭抽屉

它**不会**：

- 保存当前数据
- 判断是否有未保存改动
- 提示用户确认
- 回滚本地未保存数据

### 3. 脏状态与保存能力已经存在

- [`src/hooks/useRenovationData.ts`](file:///Users/bytedance/madiyl.github.io/src/hooks/useRenovationData.ts)
  - 已有 `isDirty`

  - 已有 `resetChanges()`

也就是说，本次不需要重新发明保存或回滚逻辑，只需要把退出交互接到已有能力上。

### 4. App 当前接线方式

- [`src/App.tsx`](file:///Users/bytedance/madiyl.github.io/src/App.tsx)
  - 当前把 `lock` 直接传给 `EditDrawer` 的 `onLock`
  - 没有任何“退出前判断脏状态”的协调层

这说明：

- 退出流程控制更适合放到 `App.tsx` 这一层
- 因为这里同时拿得到：
  - `isDirty`
  - `save`
  - `resetChanges`
  - `lock`

## Assumptions & Decisions

根据用户确认，本次锁定以下产品行为：

1. **无未保存改动时**
   - 点击“退出编辑”直接退出

2. **有未保存改动时**
   - 打开确认弹层
   - 提供三个动作：
     - 保存并退出
     - 不保存退出
     - 继续编辑

3. **保存并退出**
   - 调用现有 `save(password)`
   - 保存成功后再调用 `lock()`
   - 保存失败则保留在编辑态，并显示已有错误信息

4. **不保存退出**
   - 调用现有 `resetChanges()`
   - 然后调用 `lock()`

5. **继续编辑**
   - 仅关闭确认弹层
   - 保持当前编辑态和本地修改不变

6. **不新增额外自动保存**
   - 用户明确选择的是“先弹确认”，不是静默自动保存

## Proposed Changes

### 1. 在 App 层接管“退出编辑”逻辑

#### 文件
- [`src/App.tsx`](file:///Users/bytedance/madiyl.github.io/src/App.tsx)

#### 做什么
- 不再把 `lock` 直接作为 `onLock`
- 新增一个退出处理函数

#### 为什么
- `App` 同时拥有：
  - 脏状态 `isDirty`
  - 保存 `save`
  - 回滚 `resetChanges`
  - 真正退出 `lock`
- 这是最合适的协调层

#### 怎么做
- 新增本地状态：
  - 是否显示退出确认弹层
  - 是否正在执行“保存并退出”
- 新增函数：
  - `handleExitEditRequest()`
    - 若 `isDirty === false`，直接 `lock()`
    - 若 `isDirty === true`，打开确认弹层
  - `handleConfirmSaveAndExit()`
    - 调用 `save(password)`
    - 成功后 `lock()`
    - 关闭确认弹层
  - `handleDiscardAndExit()`
    - `resetChanges()`
    - `lock()`
    - 关闭确认弹层
  - `handleContinueEditing()`
    - 关闭确认弹层

## Data Flow / Interaction Flow

### 无改动退出

1. 用户点击“退出编辑”
2. `App` 检查 `isDirty === false`
3. 直接调用 `lock()`
4. 页面退出编辑态

### 有改动退出

1. 用户点击“退出编辑”
2. `App` 检查 `isDirty === true`
3. 打开退出确认弹层

### 选择“保存并退出”

1. 调用 `save(password)`
2. 保存成功
3. 调用 `lock()`
4. 关闭确认弹层
5. 页面退出编辑态

### 选择“不保存退出”

1. 调用 `resetChanges()`
2. 调用 `lock()`
3. 关闭确认弹层
4. 页面退出编辑态

### 选择“继续编辑”

1. 关闭确认弹层
2. 保持当前编辑态不变
3. 保留本地未保存修改

## Edge Cases & Failure Modes

- **保存并退出时保存失败**
  - 不退出编辑态
  - 保留确认弹层关闭或保持打开的策略需要统一
  - 本次建议：失败后关闭确认弹层，错误由页面现有错误区展示，用户继续手动处理

- **密码为空但编辑态仍存在**
  - 当前进入编辑态前已经完成密码校验，默认仍可继续使用已有密码变量

- **连续点击退出**
  - 确认弹层打开后，不应重复叠加多个弹层

- **正在保存时再次点击按钮**
  - “保存并退出”按钮应禁用或 loading

## Verification Steps

需要验证以下场景：

1. **无改动退出**
   - 进入编辑态但不改任何内容
   - 点击“退出编辑”
   - 直接退出，不弹确认

2. **有改动退出并继续编辑**
   - 修改任意字段
   - 点击“退出编辑”
   - 弹出确认层
   - 点击“继续编辑”
   - 保持编辑态，修改仍在

3. **有改动退出并不保存**
   - 修改任意字段
   - 点击“退出编辑”
   - 点击“不保存退出”
   - 退出编辑态
   - 重新进入后应恢复到上次已保存内容

4. **有改动退出并保存**
   - 修改任意字段
   - 点击“退出编辑”
   - 点击“保存并退出”
   - 退出编辑态
   - 刷新页面后修改仍存在

5. **工程检查**
   - `npm run check`
   - `npm run lint`
   - `npm run build`
