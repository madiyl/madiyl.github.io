# 主材多分类卡片与附件预览重构计划

## Summary

本次改动全部发生在 **主材选购** 模块，目标是把不同类别的卡片从统一结构，升级成按类别定制的内容形态。

用户要求如下：

1. **定制**：删除“最终选品”，备注下新增 Excel / PDF 预览项
2. **封窗**：删除“最终选品”，备注下新增 PDF 预览项
3. **瓷砖**：删除“最终选品”，改成单卡片内 4 个子分类，各自报价 + 汇总价格 + 底部图片
4. **木地板**：删除“最终选品”
5. **石材**：删除“最终选品”，预留 PDF 项
6. **灯光**：删除“最终选品”，预留 Excel 项
7. **窗帘**：整项删除
8. **其它**：删除“最终选品”

用户已确认的关键偏好：

- 附件结构：**双附件字段**
- Excel 预览方式：**页内弹窗预览**
- 瓷砖结构：**单卡片内 4 个子项**

## Assumptions & Decisions

本次计划锁定以下实现决策：

1. **仅重构主材选购模块**
   - 不改施工流程模块
   - 不影响设计、电器、软装页面结构

2. **删除“最终选品”的范围**
   - 作用于以下类别：
     - 定制
     - 封窗
     - 瓷砖
     - 木地板
     - 石材
     - 灯光
     - 其它
   - `施工` 当前本来已删除，保持不变

3. **附件采用双字段**
   - 主材项中补充：
     - `pdfUrl`
     - `excelUrl`
   - 各分类按需要显示，不需要的字段隐藏

4. **Excel 也走页内弹层**
   - 预览体验尽量和 PDF 一致
   - 技术上会以 `iframe` 为主
   - 若浏览器无法直接渲染某些 Excel 资源，至少保留页内入口和容器

5. **瓷砖使用专用子结构**
   - 不是复用统一 `selection/budget/actualPrice` 模式
   - 而是独立 4 个子项 + 汇总 + 图片

6. **窗帘类别完全移除**
   - 从类型、默认数据、UI 分类循环里一起删除

## Proposed Changes

### 1. 重构主材数据结构

#### 文件
- [`src/types/renovation.ts`](file:///Users/bytedance/madiyl.github.io/src/types/renovation.ts)

#### 做什么
- 扩展 `MaterialItem`
- 为瓷砖增加专用子结构类型
- 移除 `窗帘` 分类

#### 为什么
- 当前模型无法表达：
  - Excel 附件
  - 瓷砖 4 个子分类
  - 瓷砖汇总与图片

#### 怎么做
- `MaterialCategory` 删除 `窗帘`
- `MaterialItem` 补充：
  - `excelUrl: string`
- 新增瓷砖专用类型，例如：
  - `TileQuoteItem`
  - 包含 `label / selection / price`
- 在 `MaterialItem` 中补充可选字段，例如：
  - `tileQuotes?: TileQuoteItem[]`
  - `tileTotalPrice?: number`
  - `tileImagePath?: string`

注意：

- 为了兼容现有数据，新增字段应尽量是可选或带默认值

## Data Flow / Interaction Flow

### 普通主材卡片

1. 用户进入编辑模式
2. 编辑商家、预算、实价、备注
3. 保存后进入现有主材内容结构

### 附件类卡片

1. 用户在备注下填写 Excel / PDF 地址
2. 浏览态显示附件入口
3. 点击入口后打开页内预览弹层

### 瓷砖卡片

1. 用户编辑 4 个子项的名称与价格
2. 用户填写汇总价格
3. 用户填写底部图片路径
4. 页面以单张瓷砖专用卡片展示完整报价结构

## Edge Cases & Failure Modes

- **旧线上主材数据没有新字段**
  - 通过合并逻辑回落默认值
  - 不应报错

- **Excel 文件浏览器不支持直接预览**
  - 弹层仍打开
  - 可能显示浏览器默认无法渲染内容
  - 但交互不崩

- **瓷砖子项数据不完整**
  - 缺失项仍显示占位或空值
  - 不影响其它子项

- **窗帘历史数据仍存在于远端**
  - 类型与渲染层应忽略该类别
  - 页面不再展示

- **附件链接为空**
  - 不显示对应预览入口
