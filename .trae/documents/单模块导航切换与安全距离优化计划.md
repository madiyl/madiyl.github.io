# 单模块导航切换与安全距离优化计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把当前纵向连续展示的内容模块区改成“导航驱动的单模块显示”，并保证导航切换后的内容不会被 sticky 导航遮挡，同时兼顾手机与 PC 浏览器的显示合理性。

**Architecture:** 保留顶部封面区不变，把“人员介绍 + 设计阶段 + 主材选购 + 电器选购 + 施工流程 + 软装选取”收进一个受控内容容器，一次只渲染一个激活模块。导航不再做横滑分页，也不再依赖整页锚点跳转浏览所有模块，而是负责切换当前模块，并在切换时把模块容器滚动到导航下方的安全位置。

**Tech Stack:** React 18、TypeScript、Tailwind CSS、现有阶段组件与 `RenovationJourneyPage` 页面装配

---

## Summary

本轮优化聚焦 3 件事：

1. 当前页面是“一个模块一个模块往下排”的纵向流，需要改成：滚动到内容区后，只显示一个完整模块，切换到下一个模块必须点击上方导航。
2. 点击导航时，页面要把内容区域滚动到合适位置，给 sticky 导航留出安全距离，避免模块标题被压住。
3. 内容区和导航区要兼顾手机浏览器与 PC 浏览器：
   - 小屏幕导航仍可横向滚动，不挤爆
   - 大屏幕导航居中且稳定
   - 内容容器不强行等高，但要保证单模块显示完整、切换顺滑

  - 因为所有模块都实际渲染在 DOM 中，所以现在会“一路竖滑把所有模块都看完”。

### 当前遮挡问题的来源

- sticky 导航位于：
  - `className="sticky top-4 ..."`
- 各模块 section 虽然有 `id`，但没有看到任何：
  - `scroll-mt-*`
  - 自定义滚动 offset
  - `scroll-padding-top`
- 所以点击导航后，浏览器默认把锚点滚到顶部，模块标题容易被 sticky 导航盖住。

### 当前模块结构

- 已确认以下模块都各自有独立 section 和固定 `id`：
  - `people`
  - `design`
  - `materials`
  - `appliances`
  - `construction`
  - `soft`
- 这意味着模块本身已具备独立容器语义，适合被收进“单模块显示”的外层切换容器，而不必重写各模块内部布局。

## Proposed Changes

### 1. 把内容区改成“单模块显示”的受控容器

**文件：**
- 修改：[`src/pages/RenovationJourneyPage.tsx`](file:///Users/bytedance/madiyl.github.io/src/pages/RenovationJourneyPage.tsx)

**变更内容：**
- 新增页面级状态，例如：
  - `activeModuleKey`
- 用一个有顺序的模块定义数组替代当前直接顺序渲染，例如：
  - `people`
  - `design`
  - `materials`
  - `appliances`
  - `construction`
  - `soft`
- 导航下方不再同时渲染所有模块，而是只渲染当前激活模块。

**为什么这样做：**
- 用户已经明确否定了“竖滑看完整页”和“横滑切页”两种方式。
- 最符合当前诉求的是“顶部封面 + sticky 导航 + 单个内容模块”的结构。

**实现口径：**
- 封面区依然保留在最上方。
- 从导航开始进入“模块区”后，页面流里只出现当前激活模块，不再把其他模块继续往下堆。
- `PeopleIntroStage` 仍然作为第一个模块，只是不会和设计阶段同时出现在内容区。

### 2. 导航从锚点跳转改成“切换模块 + 滚动到内容容器顶端”

**文件：**
- 修改：[`src/pages/RenovationJourneyPage.tsx`](file:///Users/bytedance/madiyl.github.io/src/pages/RenovationJourneyPage.tsx)

**变更内容：**
- `navItems` 从纯 `href` 数据改为受控元数据：
  - `key`
  - `label`
- 点击导航时不再直接依赖 `<a href="#...">` 锚点跳转，而是执行两件事：
  1. 更新 `activeModuleKey`
  2. 将“当前模块容器”滚动到 sticky 导航下方的安全位置

**滚动策略：**
- 在页面中增加一个专门的模块容器 ref，例如：
  - `activeModuleRef`
- 点击导航时使用 `window.scrollTo` 或 `element.scrollIntoView + offset` 处理滚动。
- 推荐方案：
  - 先读取导航容器高度
  - 再加上固定外边距（例如 12-20px）
  - 计算目标模块容器顶部相对文档的坐标
  - 最终执行平滑滚动

**原因：**
- 这样才能同时满足：
  - 点击导航切换模块
  - 内容滚到正确位置
  - 不被 sticky 导航覆盖

### 3. 给模块内容容器增加“安全距离”机制

**文件：**
- 修改：[`src/pages/RenovationJourneyPage.tsx`](file:///Users/bytedance/madiyl.github.io/src/pages/RenovationJourneyPage.tsx)
- 可选轻量调整：各 stage 组件外层 section 的顶边距/滚动间距

**变更内容：**
- 安全距离不要再依赖浏览器默认锚点定位。
- 在导航切换时显式计算内容容器的最终停靠位置。
- 模块容器本身建议额外保留顶部间距，例如：
  - `mt-4`
  - 或者外层 wrapper 的 `padding-top`

**结果目标：**
- 模块切换后，模块标题与导航之间有稳定留白。
- 无论在手机还是 PC，标题都不会被 sticky 导航压住。

### 4. 小屏幕与大屏幕分别优化导航呈现

**文件：**
- 修改：[`src/pages/RenovationJourneyPage.tsx`](file:///Users/bytedance/madiyl.github.io/src/pages/RenovationJourneyPage.tsx)

**变更内容：**

1. 小屏幕策略
- 导航保留横向可滚动能力，避免 6 个入口挤在一行导致重叠。
- 保留当前 `overflow-x-auto` 思路，但按钮尺寸、间距、字体要略收紧。
- 目标是：
  - 单手操作可点击
  - 文案不换行
  - 不遮挡内容标题

2. 大屏幕策略
- 导航居中展示，不需要让整条导航显得过长或贴边。
- 模块内容容器可维持现有 `max-w-7xl` 范围，不额外拉满视口宽度。

3. 内容区策略
- 小屏幕：
  - 单模块完整显示
  - 垂直继续允许在当前模块内部自然滚动
- 大屏幕：
  - 同样只显示一个模块
  - 利用更宽空间展示已有网格布局（例如人员介绍、电器卡片、设计图片）

**原因：**
- 用户明确要求“区分小屏幕显示和大屏幕显示的合理性”。
- 这里不需要做两套页面，只需要让导航和模块容器在断点上有不同的布局策略。

## Assumptions & Decisions

1. 顶部封面区继续保留在最上方，不纳入单模块切换容器。
2. 导航以下的内容区一次只展示一个完整模块，其余模块不同时渲染在页面流中。
3. 点击导航的目标不是浏览器默认锚点定位，而是“切换当前模块并滚动到安全位置”。
4. 手机端导航继续允许横向滚动；PC 端则以更舒展的水平导航展示。
5. 当前各模块 section 的 `id` 可以保留，但不再作为本轮的主要定位机制。
6. 本轮不重新启用横滑切页，也不回到“所有模块整页纵向堆叠”的旧方式。

## Verification Steps

1. 单模块显示
- 打开页面后，封面区下方进入内容区时，只能看到当前选中的一个模块。
- 页面不再通过继续下滑依次看到全部模块。
- 切换到下一个模块必须点击导航。

2. 导航切换
- 点击“人员介绍”只显示人员介绍模块。
- 点击“设计阶段”后只显示设计阶段模块。
- 点击其他导航项也只显示对应模块。

3. 安全距离
- 点击导航切换后，模块标题不能被 sticky 导航遮挡。
- 模块顶部与导航之间应保留稳定留白。

4. 响应式体验
- 手机浏览器下，导航可横向滚动且按钮不拥挤。
- PC 浏览器下，导航布局稳定，模块内容不过窄也不过散。
- 各模块在小屏幕与大屏幕下都保持完整可读。

5. 回归检查
- 人员介绍模块内容仍然存在。
- 电器商品链接能力仍然存在。
- 其他阶段模块内容与编辑能力不受影响。

6. 静态检查
- 运行 `npm run check`
- 运行 `npm run lint`
- 运行 `npm run build`
