# 主材、电器、软装汇总与换行展示优化实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 修正多行文本展示、补齐主材/电器/软装三大阶段的预算汇总能力，并按最新口径重构瓷砖与灯光附件展示。

**Architecture:** 保持现有 React + TypeScript + Vite 结构不变，继续在阶段组件内做本地派生汇总，避免新增远端字段或保存流程改造。涉及结构缺口的部分仅补最小数据模型：软装条目新增 `budget` / `actualPrice`，瓷砖继续复用主材条目的 `budget` / `actualPrice`，不再使用旧的 `tileTotalPrice` 展示口径。

**Tech Stack:** React 18、TypeScript、Vite、Tailwind CSS、现有 `EditableField` / `PriceBadge` / `ImagePathField` 组件体系

---

## Summary

本次改动覆盖 7 个需求点：

1. 多行文本在展示态保留换行，并允许自然多行展开。
2. 主材选购顶部增加“总预算 / 总支出 / 差额”汇总，按当前列表条目累加。
3. 瓷砖卡片补齐“预算 / 实付”，移除“汇总价格”字段与展示。
4. 瓷砖图片保持静态展示，不提供点击预览入口。
5. 灯光附件改为 PDF，移除当前 Excel 展示入口。
6. 电器选购顶部增加“总预算 / 总支出 / 差额”汇总。
7. 软装选取新增每项“预算 / 实付”，顶部增加“总预算 / 总支出 / 差额”汇总。

## Proposed Changes

### 1. 公共展示态换行修正

**文件：**
- 修改：[`src/components/common/EditableField.tsx`](file:///Users/bytedance/madiyl.github.io/src/components/common/EditableField.tsx)

**变更内容：**
- 在展示态文本容器上增加保留换行与自然换行能力，建议使用 `whitespace-pre-wrap` 和 `break-words`。
- 不区分具体调用方，统一让所有 `EditableField` 展示态遵循相同规则。

**原因：**
- 需求截图中的“页面导语”“分享说明”都经过 `EditableField` 展示。
- 统一在公共组件修复，能覆盖后续所有多行说明类字段，避免局部补丁。

**实现决策：**
- 仅改展示态，不改编辑态 `textarea` / `input` 行为。
- 保持空态文案 `待填写` 不变。

### 2. 抽取统一的阶段汇总组件

**文件：**
- 新建：`src/components/common/BudgetSummary.tsx`

**变更内容：**
- 提供统一的“总预算 / 总支出 / 差额”展示卡。
- 入参固定为：
  - `budget: number`
  - `actualPrice: number`
  - `className?: string`
- 内部复用现有 `formatCurrency` 计算格式与差额文案，避免三处阶段组件复制相同展示结构。

**原因：**
- 主材、电器、软装三处都要加同一类汇总。
- 当前代码库已经有小型通用组件模式（如 `PriceBadge`），适合继续保持一致。

### 3. 主材阶段汇总 + 瓷砖口径重构 + 灯光 PDF 化

**文件：**
- 修改：[`src/components/stages/MaterialsStage.tsx`](file:///Users/bytedance/madiyl.github.io/src/components/stages/MaterialsStage.tsx)
- 修改：[`src/types/renovation.ts`](file:///Users/bytedance/madiyl.github.io/src/types/renovation.ts)
- 修改：[`src/lib/defaultContent.ts`](file:///Users/bytedance/madiyl.github.io/src/lib/defaultContent.ts)

**变更内容：**

1. 主材顶部汇总
- 在 `SectionHeader` 下方新增汇总区域。
- 汇总逻辑：
  - `totalBudget = materials.reduce((sum, item) => sum + (item.budget || 0), 0)`
  - `totalActual = materials.reduce((sum, item) => sum + (item.actualPrice || 0), 0)`
- 瓷砖按主材条目自身的 `budget` / `actualPrice` 参与汇总，不按分项报价自动重算总额。

2. 瓷砖卡片改造
- 在瓷砖卡片中新增与普通主材一致的“预算”“实付”字段展示与编辑入口。
- 保留 `tileQuotes` 分项报价区，用于展示每个区域的报价明细。
- 删除当前“汇总价格”输入块，不再在 UI 中展示 `tileTotalPrice`。
- 保留瓷砖底图为静态图：
  - 不传 `previewable`
  - 不提供 `onPreview`
  - 不叠加“点击放大”交互

3. 灯光附件改为 PDF
- 将 `attachmentConfig.灯光` 从 `excelUrl` 切到 `pdfUrl`。
- 浏览态统一展示“预览 PDF 附件”按钮。
- 编辑态占位文案同步改成 PDF 路径。

4. 旧字段兼容策略
- `MaterialItem` 中保留 `excelUrl?: string` 的向后兼容能力一轮，避免历史 JSON 读取时报类型不一致。
- `tileTotalPrice` 从类型上改为可选兼容字段或直接删除展示使用；无论哪种做法，界面与新默认数据都不再依赖它。
- `mergeWithDefaultContent()` 继续兼容旧 JSON，但不再给新默认数据写入 `tileTotalPrice`。

**原因：**
- 用户明确要求主材总预算/总支出来自下方项目累加。
- 用户明确要求瓷砖缺少预算/实付，且不再要汇总价格。
- 用户明确要求灯光不再是 Excel。

## Assumptions & Decisions

1. “这些地方要同步换行符；可以多行显示”按公共组件修复处理，而不是只修首页两块文案。
2. 主材总预算/总支出按 `MaterialItem` 顶层 `budget` / `actualPrice` 累加；瓷砖分项报价只作明细展示，不自动反推总额。
3. 瓷砖图片“不可以点击预览”解释为：
   - 不进入 Lightbox
   - 不出现“点击放大”悬浮提示
   - 仍保留静态展示
4. 灯光附件改 PDF 后，不再暴露 Excel 的浏览态入口；历史 `excelUrl` 仅保留兼容读取，不再写新值。
5. 软装历史数据若只有 `price`，迁移时映射为：
   - `budget = price`
   - `actualPrice = price`
   这样最符合“旧页面看起来金额不丢失”的目标。
6. 本次不调整 Supabase 表结构；所有变更都留在 `content_json` 的前端读取/写回层完成。
