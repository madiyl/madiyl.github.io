# 人员介绍模块关系强化计划_主节点连接线协作标签

## Summary

本次实现聚焦 `PeopleIntroStage` 的“任务地图感”补强，先落一版轻量但稳定的关系表达：

1. 为每个分组增加一个明确的“主节点”提示，不引入新的持久化字段。
2. 在组内卡片之间增加弱化的连接线，让它从“列表”更接近“协作网络”。
3. 给每张卡片补一个短小的协作标签，帮助快速理解它和组内主节点的关系。

本轮只做 UI 层增强，不调整 `RenovationPageData` / `PersonProfile` 数据结构，也不改变现有编辑保存逻辑。

## Proposed Changes

### 1. 在 `PeopleIntroStage.tsx` 内建立一层“展示元数据”，不改 schema

**文件：**
- 修改：[`src/components/stages/PeopleIntroStage.tsx`](file:///Users/bytedance/madiyl.github.io/src/components/stages/PeopleIntroStage.tsx)

**做法：**
- 扩展当前组件内的 `groupMeta`，补充：
  - `summaryLabel`
  - `summaryHint`
  - `badgeClassName`
  - `hubTitle`
  - `hubDescription`
  - `hubPersonId`（可选）
- 新增一个组件内的“协作标签映射”，基于稳定 `id` 返回短标签，例如：
  - `person-owner-male` -> `主决策`
  - `person-owner-female` -> `需求共识`
  - `person-uni-designer` -> `方案统筹`
  - `person-uni-materials` -> `选材联动`
  - `person-uni-construction` -> `施工落地`
  - `person-uni-admin` -> `流程对接`
  - `vendor-*` -> `供应协同`
- 保留 `updatePerson()` 现有行为，不引入新的 `onChange` 结构。

**原因：**
- 关系感是纯展示问题，当前已有稳定 `id` 足够支撑 UI 派生。
- 不改 schema，可以避免额外更新 `types`、默认数据、合并逻辑和存储层。

### 2. 每组增加“主节点说明块”，把网络中心先立起来

**文件：**
- 修改：[`src/components/stages/PeopleIntroStage.tsx`](file:///Users/bytedance/madiyl.github.io/src/components/stages/PeopleIntroStage.tsx)

**做法：**
- 组头部从当前的“两栏信息”调整为：
  1. 左侧：eyebrow、组名、成员数量
  2. 右侧：主节点说明块（hub card）
- 主节点说明块内容包含：
  - `hubTitle`，例如“主节点”
  - 该组的 `hubDescription`
  - 一条简短 summary hint
- 若 `hubPersonId` 在当前组内存在，则在说明块中展示对应成员的名称或角色作为主节点名称。
- 若该组不适合绑定到某个具体成员，则退化为“组级主节点”文案，不强行指定真人卡片。

**当前决策：**
- `业主`：主节点绑定 `person-owner-male`
- `Uni工作室`：主节点绑定 `person-uni-designer`
- `主材商`：采用组级主节点，不绑定单个商家卡片，主节点名称使用“供应协调”

**原因：**
- `业主` 和 `Uni工作室` 有明确稳定的核心角色。
- `主材商` 强行指定某个品类为中心会带入主观业务判断，不够稳。

### 3. 让卡片区从“纯网格”升级为“带骨架的关系网格”

**文件：**
- 修改：[`src/components/stages/PeopleIntroStage.tsx`](file:///Users/bytedance/madiyl.github.io/src/components/stages/PeopleIntroStage.tsx)

**做法：**
- 保留当前网格布局，不改模块级交互。
- 在卡片容器层新增一条弱化的组内“骨架线”：
  - 手机端：使用纵向 spine，放在卡片列左侧或中线，连接组内卡片
  - `xl` 以上：保留并增强现有横向连接，但改为更明确的节点式连接
- 每张卡片增加一个轻量节点标记：
  - 主节点卡片：顶部或左上角增加 `主节点` badge，并用更明显的边框/背景层级
  - 非主节点卡片：通过小圆点或短连线接入骨架
- 连接线全部通过普通 DOM + Tailwind 类完成，不引入 SVG / Canvas。

**原因：**
- 目标是“更像协作网络”，不是做一套复杂图编辑器。
- 使用 CSS 装饰线可以兼容当前响应式结构，也更容易控制密度。

### 4. 调整卡片信息层级，让关系信息出现在头像和正文之间

**文件：**
- 修改：[`src/components/stages/PeopleIntroStage.tsx`](file:///Users/bytedance/madiyl.github.io/src/components/stages/PeopleIntroStage.tsx)

**做法：**
- 浏览态卡片顺序调整为：
  1. 头像区
  2. 关系标签行（如 `主节点` / `方案统筹` / `供应协同`）
  3. 名称
  4. 角色
  5. 备注
- 编辑态仍保留现有可编辑字段，但展示态优先突出“谁 + 与网络的关系”。
- 继续保留空备注隐藏逻辑；如果备注过长，可在浏览态补一层摘要/展开结构，但本轮只在不增加明显复杂度时顺手实现，不作为必须交付项。
- 对没有头像的卡片，补默认头像块，避免关系线已经更明显但头像区域仍然空掉。

**原因：**
- 当前顺序里“角色”先于“名称”，更像表单，不像名片。
- 关系标签如果继续埋在正文后面，网络感会被抵消。

## Assumptions & Decisions

1. **本轮不修改 `PersonProfile` 类型，也不新增数据库字段。**
   - 所有主节点和协作标签都由组件内元数据派生。

2. **主节点规则固定在组件内，不依赖用户编辑后的名称/角色文案。**
   - 以稳定 `id` 为主，避免用户修改 `role` 后关系判断失真。

3. **`主材商` 组采用组级主节点，而不是指定某一个供应商卡片为中心。**
   - 这是为了避免“定制/封窗/瓷砖谁更核心”的主观偏差。

4. **这一版只动 `PeopleIntroStage` 与其测试。**
   - 不联动 `RenovationJourneyPage.tsx`、`defaultContent.ts`、`types/renovation.ts`。

5. **连接线属于辅助视觉，不做强交互。**
   - 不增加 hover 高亮、点击聚焦、拖拽等行为。
