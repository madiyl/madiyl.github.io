# 横向分页导航与人员介绍模块优化计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为装修记录页增加人员介绍模块、电器商品链接能力，并把内容区域从纵向滚动改成基于导航切换的横向分页浏览。

**Architecture:** 保留现有顶部封面区不变，把“人员介绍 + 五个阶段模块”收进一个受控的横向分页容器，由导航条驱动当前页切换，同时支持手势横滑。数据模型只做最小扩展：新增 `people` 模块和电器的 `productUrl` 字段，浏览态对商品链接只展示域名前缀，点击后跳转到完整链接。

**Tech Stack:** React 18、TypeScript、Framer Motion、Tailwind CSS、现有 `EditableField` / `SectionHeader` / 阶段组件结构

---

## Summary

本轮改动覆盖 3 个功能点：

1. `电器选购` 每个商品卡新增可编辑链接字段；浏览态不展示完整 URL，只显示短链前缀（已确认采用域名前缀，如 `jd.com`），点击跳转到完整商品链接。
2. 在 `设计阶段` 之前新增 `人员介绍` 模块，包含男主人、女主人、设计老师、预算老师、施工老师，以及对应头像与可编辑内容。
3. 取消当前内容模块的纵向连续滚动，把导航条改成真正的分页切换入口；顶部封面区保留在上方，下面从 `人员介绍` 开始使用横向分页模块，支持导航切换和横滑切换。

### 3. 电器模块增加商品链接输入与短前缀展示

**文件：**
- 修改：[`src/components/stages/AppliancesStage.tsx`](file:///Users/bytedance/madiyl.github.io/src/components/stages/AppliancesStage.tsx)
- 可选新建：`src/utils/url.ts`

**变更内容：**

1. 编辑态
- 在每张电器卡内新增 `商品链接` 字段。
- 仍使用 `EditableField`，允许粘贴完整 URL。

2. 浏览态
- 如果 `productUrl` 存在：
  - 只显示域名前缀，如 `jd.com`
  - 整个链接区可点击，`target="_blank"` 打开完整链接
- 如果 `productUrl` 为空：
  - 不展示该区块

3. URL 归一化策略
- 建议新增一个小型工具函数：
  - 输入完整 URL
  - 解析 `hostname`
  - 去掉常见 `www.` 前缀
  - 返回短展示文本
- 若 URL 无法解析：
  - 浏览态降级显示 `查看商品`
  - 编辑态仍保留原始值

**原因：**
- 展示完整 URL 会破坏卡片视觉密度。
- 解析 hostname 是稳定、可复用且最接近用户已确认口径的做法。

### 4. 把内容区改成横向分页容器

**文件：**
- 修改：[`src/pages/RenovationJourneyPage.tsx`](file:///Users/bytedance/madiyl.github.io/src/pages/RenovationJourneyPage.tsx)
- 可选新建：`src/components/layout/ContentPager.tsx`

**变更内容：**

1. 分页范围
- 顶部封面区保留当前纵向位置不变。
- `人员介绍 + 设计阶段 + 主材选购 + 电器选购 + 施工流程 + 软装选取` 收进同一个内容分页容器。

2. 导航从锚点改为受控分页
- 现有 `navItems` 改成分页元数据，例如：
  - `key`
  - `label`
- 点击导航时不再跳 `href="#..."`，而是更新当前分页索引。

3. 横滑实现
- 内容层采用“横向滚动 + scroll snap”或“受控 translateX 容器”两种方式之一。
- 本次建议采用：
  - CSS `overflow-x-auto`
  - `snap-x snap-mandatory`
  - 每页 `w-full shrink-0`
  - 配合 React state 跟踪当前页
- 原因：
  - 实现简单
  - 兼容触控横滑
  - 不必引入新的轮播依赖

4. 分页同步
- 导航点击要能滚动到对应页。
- 用户手势横滑后，当前高亮导航要同步变化。
- 需要监听页面滚动位置或使用 `IntersectionObserver` / `scrollLeft` 推断当前页。

5. 页面高度策略
- 不强制所有分页等高。
- 每个模块页保持自然高度，分页容器整体允许随当前页内容高度变化。
- 这样可以避免短页/长页都被硬撑成视口高度，减少布局僵硬感。

**原因：**
- 用户明确要求“不一直下滑显示”，而是通过导航分页 + 横滑查看不同模块。
- 仅保留锚点导航无法满足这个需求。

## Assumptions & Decisions

1. 顶部封面区不参与横向分页，仍固定在分页容器上方。
2. 人员介绍采用固定 5 人模型，不提供新增/删除入口，只做内容编辑。
3. 电器商品链接的浏览态展示采用 `hostname` 级别短前缀，而不是保留路径或展示完整短链。
4. 横向分页优先采用原生滚动 + scroll snap，而不是引入轮播库。
5. 各分页模块保持自然高度，不强制每页满屏。
6. 这轮改动只重构“内容模块”的浏览方式，不调整顶部封面文案、保存机制或 Supabase 接口。
