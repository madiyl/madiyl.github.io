# 电器选购模块卡片逻辑优化计划_选项图片与目录清单

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 重构电器选购模块卡片逻辑，支持枚举化购买渠道与状态、商品链接、目录清单驱动的多图预览，以及更接近主材模块的价格展示。

**Architecture:** 保留当前“一个品类一张卡”的整体结构，不改页面级导航和模块顺序。核心改动集中在 `ApplianceItem` 数据模型和 `AppliancesStage` 渲染层：将部分自由文本字段升级为受控选项，新增图片目录与图片清单数据，复用现有 `ImageLightbox` 完成多图放大预览，并通过 `manifest.json` 解决静态站点无法运行时列目录的问题。

**Tech Stack:** React 18、TypeScript、Tailwind CSS、Vite 静态资源、现有 `ImageLightbox` / `PriceBadge` / `BudgetSummary`

---

## Summary

本轮电器模块优化包含 6 个落点：

1. 购买渠道改成受控选项：`电商平台`、`线下门店`、`团购`
2. 每张电器卡新增：
   - 购买链接
   - 图片目录字段
   - 根据目录读取 `manifest.json` 后得到的多图预览能力
3. 预算和成交价的展示效果向主材模块靠拢，增强对比感知
4. 状态改成受控选项：`选品`、`加购`、`已购`
5. 卡片右上角显示一张小封面，只显示首图，点击可进入多图放大预览
6. 图片输入不再是一张张 URL，而是填一个目录路径；前端读取该目录下的 `manifest.json`，按清单或文件名顺序展示

  - [`vite.config.ts`](file:///Users/bytedance/madiyl.github.io/vite.config.ts)
  - 没有运行时目录列举能力
  - 也没有现成的 `import.meta.glob` 目录映射逻辑

**关键事实：**
- 纯静态站点不能在浏览器里可靠地“读取文件夹里的所有文件名”
- 你已经确认这块改成：
  - `目录 + manifest.json`

这意味着实现上应依赖类似：

```text
/uploads/renovation/product/tv/
  manifest.json
  01.jpg
  02.jpg
```

前端通过目录路径拼出 `manifest.json` 并读取清单，而不是直接扫目录。

## Proposed Changes

### 1. 升级 `ApplianceItem` 数据结构

**文件：**
- 修改：[`src/types/renovation.ts`](file:///Users/bytedance/madiyl.github.io/src/types/renovation.ts)
- 修改：[`src/lib/defaultContent.ts`](file:///Users/bytedance/madiyl.github.io/src/lib/defaultContent.ts)

**变更内容：**

1. 为购买渠道和状态补类型约束
- 新增：
  - `ApplianceChannel = "电商平台" | "线下门店" | "团购"`
  - `ApplianceStatus = "选品" | "加购" | "已购"`

2. 扩展 `ApplianceItem`
- 保留现有：
  - `productUrl`
- 新增：
  - `imageDir: string` 用于填写目录路径，例如 `/uploads/renovation/product/tv`
  - `imageManifest?: string[]` 或等价的图片路径数组，用于保存已解析的多图结果

**推荐决策：**
- 数据层只持久化 `imageDir`
- `imageManifest` 不写入主数据，作为运行时派生状态在组件内加载

这样更干净，也避免把静态清单内容重复存进数据库。

3. 默认内容更新
- 首个示例电器可以给一个空目录或样例目录。
- `channel` 默认值从任意字符串改成三选一之一。
- `status` 默认值从 `待选购` 改为 `选品`。

4. 兼容旧数据
- `mergeWithDefaultContent()` 中对旧 `appliances` 做兼容补齐：
  - 若 `channel` 不是三种之一，回退默认值
  - 若 `status` 不是三种之一，回退默认值
  - 若缺失 `imageDir`，补空字符串

### 2. 为电器图片目录新增 `manifest.json` 读取逻辑

**文件：**
- 新建：`src/utils/applianceImages.ts`
- 修改：[`src/components/stages/AppliancesStage.tsx`](file:///Users/bytedance/madiyl.github.io/src/components/stages/AppliancesStage.tsx)

**变更内容：**

1. 新增工具函数
- 建议提供：
  - `normalizeImageDir(path: string): string`
  - `getManifestUrl(dir: string): string`
  - `loadApplianceImages(dir: string): Promise<string[]>`

2. Manifest 格式
- 推荐使用最小 JSON 结构：

```json
{
  "images": ["01.jpg", "02.jpg", "03.jpg"]
}
```

- 前端读取后拼成完整 URL：
  - `${dir}/01.jpg`
  - `${dir}/02.jpg`

3. 排序口径
- 若 manifest 的 `images` 已提供顺序，则按 manifest 顺序展示
- 若后续要兼容“仅给文件名数组但无排序字段”，也仍按数组顺序即可
- 不在浏览器里再做目录排序猜测

4. 加载时机
- 浏览态和编辑态都可以读取图片清单，但实际展示只在有 `imageDir` 时触发
- 图片清单建议在 `AppliancesStage` 内部按 `item.id` 缓存，避免重复 fetch

**原因：**
- 这是静态站下最稳定、可维护的目录式图片方案。

## Assumptions & Decisions

1. 图片目录方案采用 `目录 + manifest.json`，不做运行时目录扫描。
2. `manifest.json` 的 `images` 数组顺序就是最终展示顺序。
3. 电器卡片右上角采用“小封面图”而不是右侧大分栏图片区。
4. 渠道和状态都改成受控枚举，不再接受任意自由文本。
5. 电器图片清单作为运行时派生状态，不直接写回主数据。
6. 这轮只改电器模块，不扩展到其它模块的目录式图片管理。
