# 免密编辑与协作方地图及预览卡片优化计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 临时关闭编辑密码门禁，同时把人员介绍升级为分组的“协作方地图”，并优化设计阶段图片预览与主材卡片的视觉层次。

**Architecture:** 保留当前“封面区 + 单模块导航切换”的页面结构，只调整四个局部能力：编辑鉴权链路、协作方数据模型与展示、图片 Lightbox 视觉比例、主材卡片的状态与空备注展示。对于免密要求，本次按用户确认同时覆盖前端进入编辑和后端保存校验，避免出现“能进编辑但保存失败”的半改状态。

**Tech Stack:** React 18、TypeScript、Tailwind CSS、Supabase Edge Function、现有 `RenovationJourneyPage` / `PeopleIntroStage` / `ImageLightbox` / `MaterialsStage` 组件体系

---

## Summary

本轮优化覆盖 4 个目标：

1. 编辑入口临时免密，且保存链路也临时免密，后续再恢复。
2. 人员介绍模块改造成分组的“协作方地图”：
   - 业主：男主人、女主人
   - Uni工作室：设计师、主材老师、施工老师、行政老师
   - 主材商：定制、封窗、瓷砖、木地板、石材、灯光
3. 设计阶段图片预览中的主图更大，左右切换按钮更轻更小。
4. 主材模块中：
   - `已选方案` 与 `对比方案` 颜色做更明显区分
   - `备注` 在浏览态为空时不展示

## Proposed Changes

### 1. 临时关闭前后端编辑密码门禁

**文件：**
- 修改：[`src/hooks/useEditMode.ts`](file:///Users/bytedance/madiyl.github.io/src/hooks/useEditMode.ts)
- 修改：[`src/components/editor/EditDrawer.tsx`](file:///Users/bytedance/madiyl.github.io/src/components/editor/EditDrawer.tsx)
- 修改：[`src/App.tsx`](file:///Users/bytedance/madiyl.github.io/src/App.tsx)
- 修改：[`src/lib/contentApi.ts`](file:///Users/bytedance/madiyl.github.io/src/lib/contentApi.ts)
- 修改：[`supabase/functions/save-renovation-page/index.ts`](file:///Users/bytedance/madiyl.github.io/supabase/functions/save-renovation-page/index.ts)

**变更内容：**

1. 前端进入编辑免密
- `useEditMode.authenticate()` 不再调用 `verifyEditPassword()`。
- 直接进入 `editMode`，并关闭抽屉。
- `canSubmit` 改成仅依赖 `!authenticating` 或直接移除密码非空条件。

2. 编辑抽屉文案与表单同步简化
- 去掉密码输入框和“验证并进入编辑”的门禁文案。
- 保留编辑抽屉作为“编辑控制面板”，展示：
  - 进入编辑
  - 保存当前改动
  - 撤销未保存改动
- 文案改成临时免密状态，例如“当前为临时免密维护模式”。

3. 保存链路免密
- `App.tsx` 中 `save(password)` / `handleSaveAndExit()` 改成不再依赖密码输入值。
- `useRenovationData.save()` / `saveRenovationPageData()` 接口可改为：
  - 不再强制传密码
  - 或接受可选密码但本轮调用传空字符串

4. Edge Function 临时免密
- 在 `save-renovation-page` 函数里，对 `verify` 和 `save` 临时跳过 `password !== expectedPassword` 这段校验。
- 保留 `EDIT_PASSWORD` 相关结构不删除，只改成“本轮不启用”或通过一个临时开关绕过，便于后续恢复。

**原因：**
- 用户要求不是“仅免进门”，而是“现在进入编辑不需要输入密码，后面再打开”。
- 要满足这个要求，前后端必须同步改。

### 2. 把 `people` 升级成分组的协作方地图数据结构

**文件：**
- 修改：[`src/types/renovation.ts`](file:///Users/bytedance/madiyl.github.io/src/types/renovation.ts)
- 修改：[`src/lib/defaultContent.ts`](file:///Users/bytedance/madiyl.github.io/src/lib/defaultContent.ts)
- 修改：[`src/components/stages/PeopleIntroStage.tsx`](file:///Users/bytedance/madiyl.github.io/src/components/stages/PeopleIntroStage.tsx)

**变更内容：**

1. 类型升级
- 将当前 `PersonProfile` 提升为更通用的协作方节点模型，建议新增字段：
  - `group: "业主" | "Uni工作室" | "主材商"`
  - `role: string`
  - `name: string`
  - `avatarPath: string`
  - `note: string`
- 保持现有 `people` 数组入口不变，避免页面其他引用大改。

2. 默认数据替换为新的 12 个节点
- `业主`
  - 男主人
  - 女主人
- `Uni工作室`
  - 设计师
  - 主材老师
  - 施工老师
  - 行政老师
- `主材商`
  - 定制
  - 封窗
  - 瓷砖
  - 木地板
  - 石材
  - 灯光

3. 兼容旧数据
- `mergeWithDefaultContent()` 需要兼容历史 5 人结构：
  - 如果旧数据没有 `group`，按角色名映射默认分组
  - 旧的 `预算老师` 可归并到 `Uni工作室`，或者在兼容期保留其 `name/note` 但映射到新角色槽位时需给明确策略
- 本次推荐做法：
  - 用新的默认节点数组作为基底
  - 旧数据按 `role` 匹配相近槽位覆盖
  - 匹配不到的旧条目作为补充项挂到 `Uni工作室` 或保留为独立节点

**原因：**
- 用户已经明确要求用“分类 + 任务地图”表达，不再是纯人物卡。
- `主材商` 也需要进入同一套结构，因此必须从“人”扩展为“协作方节点”。

### 3. 将人员介绍模块重构为“任务地图”式分组卡片

**文件：**
- 修改：[`src/components/stages/PeopleIntroStage.tsx`](file:///Users/bytedance/madiyl.github.io/src/components/stages/PeopleIntroStage.tsx)

**变更内容：**

1. 展示结构
- 顶层按组渲染 3 个分区：
  - 业主
  - Uni工作室
  - 主材商
- 每个分区用独立容器，带组标题和说明。

2. “任务地图”风格
- 不再使用现在的完全等价平铺网格。
- 改为“分区 + 节点卡”的视觉结构：
  - 每组一个大容器
  - 容器内是若干较小节点卡
  - 节点卡之间保留路线感/任务流感的排布，例如更紧凑的栅格、连线感背景或组内分层
- 不引入复杂 SVG 图谱，只在现有 Tailwind 能力内做“地图感”的层次。

3. 节点内容
- 每个节点继续支持：
  - 图片/头像
  - 角色
  - 名称
  - 备注
- 对于 `主材商` 这一组，`name` 可以填商家名或当前合作方名称，`role` 是“定制/封窗/瓷砖...”。

4. 编辑约束
- 仍不做新增/删除入口。
- 只允许编辑已有节点内容。

**原因：**
- 用户要的是“类似一个任务地图”，不是简单换个标题。
- 但也没要求引入复杂交互，因此应采用视觉地图而不是重型流程图组件。

### 4. 放大设计阶段图片预览主图，缩小左右切换按钮

**文件：**
- 修改：[`src/components/common/ImageLightbox.tsx`](file:///Users/bytedance/madiyl.github.io/src/components/common/ImageLightbox.tsx)

**变更内容：**

1. 主图变大
- 提升主图可用高度，例如：
  - 外层容器维持或略增 `max-w`
  - 主图容器 `min-h` 增大
  - 图片 `max-h` 从当前 `58vh` 提升到更高值
- 目标是让设计图在大屏预览时更接近“主视角”。

2. 左右按钮变小
- 按钮尺寸从当前大胶囊收紧：
  - 缩小 padding
  - 缩短文案，必要时改用更轻量符号/更短文本
  - 减弱视觉重量，避免抢图

3. 保持现有结构
- 继续保留：
  - 右侧缩略图栏
  - 底部标题/说明区
  - 键盘左右切换

**原因：**
- 用户只要求“图更大、按钮更小”，不是重做整个 Lightbox。
- 这是典型的局部视觉优化，适合在现有结构上微调比例。

### 5. 强化主材卡片的“已选 / 对比”状态差异，并隐藏空备注

**文件：**
- 修改：[`src/components/stages/MaterialsStage.tsx`](file:///Users/bytedance/madiyl.github.io/src/components/stages/MaterialsStage.tsx)

**变更内容：**

1. 状态色差异
- `已选方案`
  - 使用更明确的主色/暖色/高亮底色
- `对比方案`
  - 使用更弱的中性色/浅灰棕底色
- 保持两者都与当前站点综合色系一致，不做突兀高饱和色。

2. 空备注不展示
- 在浏览态下：
  - 如果 `note.trim()` 为空，则不渲染“备注”区块
- 在编辑态下：
  - 仍保留 `备注` 输入框
- 适用于：
  - 普通主材卡
  - 瓷砖卡的备注区

**原因：**
- 方案状态需要更快被识别。
- 空备注在浏览态只会制造“待填写”噪音，应该去掉。

## Assumptions & Decisions

1. “现在进入编辑不需要输入密码，后面再打开”按“进入编辑 + 保存都临时免密”执行，且前后端同步调整。
2. `people` 模块继续沿用数组入口，但语义升级为“协作方节点”，不再局限于“人物”。
3. 人员介绍的“任务地图”采用分组式地图感卡片，不引入复杂可视化引擎。
4. Lightbox 只做比例和按钮尺寸微调，不改预览交互逻辑。
5. 主材空备注仅在浏览态隐藏，编辑态仍然可以填写。
6. 本轮不改导航单模块切换逻辑，不触碰与本次需求无关的页面装配方案。
